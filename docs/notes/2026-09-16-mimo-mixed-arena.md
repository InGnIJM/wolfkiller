# 评测快照：MiMo v2.5 vs MiMo v2.5 Pro 混座十人场

- 日期：2026-09-16
- 事实源：本机 `backend/data/wolfkiller.sqlite3` 与各局 `summary.json`（不在 git 里）
- 运行：`0bf6d7e3-0256-4b3e-96eb-0673e86df546`（`mixed_arena`，状态 `paused`）
- 口径：原生报告 `metric_version=v2`（胜率 / 请求质量 / 延迟）；决策质量用现有 `app.benchmark.metrics` 从 61 份完成局 `summary.json` 重算
- 这不是门禁，也不是全模型结论。只覆盖这一次混座，且 **v2 报告本身不含决策质量表**

## 设置

| 项 | 值 |
| --- | --- |
| 板子 | 十人标准场（3 狼 3 民 1 预言家 1 女巫 1 猎人 1 守卫） |
| 模型 | 小米 MiMo v2.5 ×5 与 MiMo v2.5 Pro ×5，随机落座 |
| 计划 | 100 局，并发 4，单局超时 3600 秒 |
| 进度 | 完成 61，超时失败 22，未开跑 13，检查点损坏卡住 4 |

两模型阵营胜率几乎打平（好人约 46%，狼人约 54%），分角色也看不出 Pro 稳定优于 base。这次评测比较的是「同系列大小号混座」，不是 Gemini / GLM / DeepSeek。

## 对局结果（61 局完成）

| 指标 | 值 |
| --- | --- |
| 狼人胜 / 好人胜 | 54.1% / 45.9% |
| 平均 / 中位天数 | 4.23 / 4（最短 2，最长 8） |
| 完成局墙钟 | 中位 28.2 分钟，最短 16.2，p95 39.8，最长 41.0 |
| 每局 LLM 调用（summary 口径） | 约 111 次 |

22 局失败原因全部是 `benchmark_game_timeout`，不是规则算错。4 局 `recovery_blocked` / `checkpoint_corrupt`。跑批仍暂停，13 局从未启动。

## 决策质量（从 summary 重算）

跨局命中率（机会数作分母）：

| 指标 | 值 | 怎么读 |
| --- | --- | --- |
| 预言家验中狼 | 38.1%（97 次查验） | 十人 3 狼随机约 30%，略高于乱猜 |
| 女巫毒药命中狼 | 78.8%（33 次下毒） | 毒很准；解药用了 55 次 |
| 狼刀命中神职 | 64.8%（128 次刀） | 狼刀优先打神 |
| 好人白天投票命中狼 | 40.4%；弃票 21.0% | 白天认狼一般 |
| 放逐命中狼 / 误伤神职 | 33.8% / 37.1% | 放逐神职比放逐狼还多 |
| 猎人开枪带狼 | 0%（n=1） | summary 里 61 局只有 1 次 `HUNTER_SHOT`，带走的是预言家。次数过少，不能下「猎人很差」的结论 |

**不要用 v2/旧文档里那条跨局 `wolf_vote_concentration`。** 它按座位号把 61 局的狼票堆在一起，混座局里会得到约 12.6%、10 个不同目标这种假信号。8 月底「约 27%」是 4 局小样本加同一口径，同样不能当协同结论。

按**每一轮白天、至少两票狼票**重算（180 轮）：

- 轮次集中度中位 **100%**，均值 **84.5%**
- **61.7%** 的轮次狼人白天投同一人

也就是说：在这 61 局里，狼人白天经常对齐；好人白天则更容易放逐神职。夜间狼刀打神也偏准。更值得看的是女巫毒准、白天屠神，而不是「狼不会抱团」。

## 延迟与直播体感

原生 v2 对全部 11815 次模型尝试：

| | p50 | p95 | p99 |
| --- | --- | --- | --- |
| 尝试延迟 | 14.7s | 59.8s | 126.7s |

分动作（同一批尝试）：

| 动作 | 次数 | p50 | p95 | >60s |
| --- | --- | --- | --- | --- |
| 白天发言 | 4088 | 13.5s | 41s | 112 |
| 白天投票 | 4092 | 21.4s | 73.5s | 404 |
| 狼队讨论 | 1212 | 6.9s | 37s | 19 |
| 狼刀 | 1290 | 6.8s | 20s | 5 |

发言必须串行：十人一轮中位大约两分钟只花在等模型。时间轴 0.5x–8x 只加快**已经落盘**的事件，不能缩短这次等待。Pro 的发言/投票长尾明显长于 base（发言 p95 约 56s vs 28s）。

狼队讨论/刀口上有大量 `model_invocation_error`（约 1565 次，接近全量 1580 次失败）。这会拖夜间，也会让部分刀口走降级；未区分是超时、协议还是解析，不要直接当成「提示词导致不协同」。

## 文档口径要注意的

- 原生 v2 报告（评测页 / `GET /api/benchmarks/{id}/report`）只有胜率、请求成功/弃权/失败、延迟。决策质量仍在 `summary.json` + `app.benchmark.metrics`，**没有进 v2，评测页也看不到**。
- `docs/benchmark.md` 里 Markdown 决策表描述的是旧 summary 聚合，不是当前 API 报告 JSON。
- 用量完整性只有约 8%：MiMo 大多不回 token，v2 里那 258 万 token 只代表有用量的 937 次尝试。

## 对后续工作的含义

1. 这一次已经够看趋势（完成局 > 30），阵营胜率接近屠边预期，不必再靠 8 月底那 4 局说话。
2. 观赛卡顿的主因是串行等模型，不是缺暂停/加速。
3. 若继续做质量，优先看白天屠神、女巫毒线和猎人开枪是否真写进了 summary；不要再引用跨局狼票集中度。
